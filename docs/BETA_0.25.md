# 0.25.0 beta testing

Development happens on `dev/0.25.0`. The stable `main` branch and `v0.24.0` release are not replaced by this branch.

## Compatibility and isolation

Opening JSON schemas and saved field names are unchanged. Copy your own opening JSON files into the beta application's `Openings` directory. Keep an original backup; do not overwrite a generated opening with a bundled example. The beta can read openings generated by 0.24.0.

For isolated testing, set `CHESS_TRAINER_DATA` to a separate directory before launching the beta. Without that override, both versions use the existing per-user data location. Do not run both versions against the same writable profile simultaneously.

## Opening generation queue

Submitting a job freezes its start position and settings. The arrows switch between snapshots; **Create another job** opens a draft. **Process this job next** moves a queued job to the front. Jobs share persistent engine workers: free workers may process pending positions from lower-priority jobs, but an active engine search finishes before switching jobs.

The highest-priority runnable job defines the shared worker/thread budget. A job at its card limit waits for approval while other jobs may continue. The option below the card limit can instead pause the whole queue. Closing the generator asks before cancelling active jobs and saves available partial trees. Queue state is scoped to the open generator window; it is not a durable crash-recovery queue.

The graph button opens one independent preview window. It shows the selected graph and, with multiple jobs, two adjacent progress bars with per-job and overall information in separate columns. Predictions can decrease when observed branches terminate earlier than expected; displayed progress does not move backwards. Completed estimates become the actual card count. Timing estimates are approximate; work intervals exclude queued and approval-waiting time. Optional cooling breaks are configured under **Branches**, finish current searches first and do not disable the other training modes.

An unsent draft remains available through the navigation arrows. Only one unsent draft is kept at a time. Clearing completed jobs removes them from the queue view, not from the saved opening library. Completed jobs offer direct **View branch** and **Learn** actions.

## Branches and save-a-piece exercises

Extraction copies the selected position variant, its descendants and a shortest legal approach sequence into a new opening. The original graph and progress remain unchanged. Initial graph preparation runs outside the UI thread; the loading indicator remains responsive. A bounded geometry cache accelerates repeated layouts without sharing mutable window state. Crossing reduction skips pairs of edges that cannot geometrically cross.

Save a Piece requires exactly one geometrically safe destination and an engine-verified move within one pawn of the best move at depth 10. This is a bounded engine check, not a proof of optimal play.

## Audio diagnosis

Code inspection found a race between asynchronous media loading and playback, plus synchronous dispatcher waits. The beta waits for media readiness, posts audio work asynchronously and lowers background engine process priority. These changes address program-side risks under CPU load; they do not establish that every audio-device or driver issue is fixed. Record the sound pack, workload and whether other applications also stutter when reporting a recurrence.

## Guided overview

The embedded first-run card includes language selection. Restart it at the top of General settings. Informational steps accept Space; interactive steps wait for the requested action, with Space also available for the lesson card buttons. Back/forward arrows review previous information. Other application windows are dimmed and offer cancellation; hover board previews remain available. Tutorial learning and the sample game use a separate `Tutorial` data directory. The temporary statistics-demo setting and previously selected learning opening are restored on exit.

Both development and public packages use the curated English and Pirc examples. Bookmarks are stored by opening ID in the local profile; bookmarked openings sort first, followed by alphabetical name.

## Before stable promotion

Test queue approval, reprioritization, cancellation, multi-job preview, both tutorial languages and real audio under generation load. Run the private local regression suite and inspect its results. Merge the development branch only after review; a passing build alone is not stable-release acceptance.
